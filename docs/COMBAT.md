### 0.1 设计主轴：Noita 式"可组合" + 结构装载体（用户 2026-09-13 定）
**Noita 真正值得学的不是"法术多"，而是三件事**：① 少量**正交原语**（发射器 / 修饰器 / 载荷）② 一条**组合规则**（按顺序施加、逐个影响同一发）③ **确定性**（同样组合→可复现的行为）。所以本作要学的不是"加 20 种塔"，而是**把塔拆成可组合的载荷**。

**本作已有的地基（这条最关键）**：棱镜光路**已经是接力式组合** —— `PRISM_MAX_HOPS = 8`、每段从上一段取光、**断一环整条熄灭**。也就是说"光路"本来就是一根**可插拔的网线**，我们要做的只是在线上定义**载荷**。

**两条落地方针**：
1. **不做无限组合，做"有限槽位 + 开放效应"**：修饰器 ≤3 个/塔、槽位由研究解锁 → 有效组合量级在几十种（**可穷举、可断言**）。Noita 靠"随机生成 + 玩家自己发现"消化无限组合；本作是基地经营 + 有限波次，无限组合会直接把平衡与可读性一起吃掉。
2. **燃料就是"法力"**：组合越强 → 每秒燃料消耗越高 → **你的塔越强，你的灯就越暗**。组合系统天然被已有经济（灯也烧燃料）约束住，不需要额外平衡器。这是整套设计里最漂亮的一环，必须守住。

**结构装载体**：本质是"**能背着走的光源 + 炮台**"，它**强化**而非绕过"光即生命"（你在哪，光就在哪）。代价三条必须同时存在：移动中射速减半 / 背负时占背包格且燃耗 ×1.5 / 本体有 hp，**被啃掉就真丢**（不回背包）；装卸要停下来按住 E 完成。

**三方位共用基建（只做一次，放在 A 的第 0 步里）**：
- 数值中央化：所有玩法常量收进 `data/` 下的单一数据源（B13 的教训：**表与实现分家必然出事**）
- 战斗/生存/生态专用调试口（`__wave()` / `__dps()` / `__eco()`）
- 检测器新增断言（数值范围、账本、上限、行为标志）
- 一个"**标准局回放**"脚本：固定种子 + 固定打法，跑 N 天，输出曲线表 → 以后每步改完都跑它对比

### 1.2 波次（`systems/waves.js`）
- 只在**黑暗**里出现（光照 ≥0.5 的格子不刷）→ **光照封锁**是核心机制 ✓
- `tide = min(day, 8)`；`cap = (20 + tide*6 + bossNight*10) × diff.capMul`；`interval = max(1.9, 4.2 − tide*0.22) × waveMul`
- 种类靠 `kindFor(tide, rnd)` **纯随机**（潮位越高越凶）
- **蚀痕 ≥2 格刷出的怪 +15% 血/伤**
- Boss：每 7 天一次，`Boss 血量 ×(1 + bossTier×0.55)`（越打越强）

### 1.4 死亡与容错
- 死亡 → 回营地 + 燃料减半 + 场上怪全清 + **跳黎明**（只对黄昏/蚀潮有效，B20 已修）
- 研究里有 6 条战斗线（光爆威力/塔伤/塔射速/对空/血上限/耐热）

### 1.5 **最有价值的现状结论**
1. **`applyDamage()` 是统一入口**，但**没有类型/抗性** → 图鉴里那句"任何伤害都高效"只是文案，**机制上不存在克制**。这是最便宜也最有效的一刀。
2. **玩家只有 1 个动作**（空格）→ 夜战没有"操作表达空间"，这是体验最薄的地方。
3. **光照既是防御也是武器**（塔要光、怪只从黑暗出）→ 这是本作**最独特**的战斗机制，但目前只用了一层（"站在光里"）。真正的深挖方向是"**光的攻防**"：抢光、断光、把光送出去。
4. `kindFor()` 纯随机 → 缺少"**主题夜**"（蛾潮夜 / 壳潮夜），夜与夜之间没有记忆点。
5. 塔**不能升级**，只有全局研究加成 → 前中期塔一旦铺满就没有成长曲线。
6. **棱镜光路已经是"接力式组合"**（`PRISM_MAX_HOPS = 8`、每段从上一段取光、断一环整条熄灭）→ 这就是 Noita 式载荷框架**天然的地基**：光路本就是那根"可插拔的网线"，而目前它只用来传光，没用来"装东西"。

**撤回记录：为什么“工具能攻击”被删掉（D47）**

用户只看了一眼实机就否了，理由与我的复盘一致：
1. **概念割裂**：工具在玩家的心智里是“生产件”，忽然要他去背一张“镐打壳 ×1.6、镰打不动壳”的表；而这游戏的战斗语言本来是 **光**（塔/光爆/绕光）+ 现在的**背塔**。
2. **抢 E 的手势**：近战排在 `resolveInteractAt` 的**第 0 位**（最高优先级）→ 鼠标指着怪时 `E` 不再采集/施工/开面板。这恰好把 B48 刚理顺的“鼠标指哪就交给谁”又搞浑了一一而玩家真正想干的事（采矿）被抢了。
3. **没必要**：深潜贴脸的自保手段已有三条更清楚的线：**辉光棒（F，耗燃料）/ 光爆 / 背上的塔**。

删除内容：`MELEE` 常量、`meleeHit()`、`resolveInteractAt` 的 attack 分支、`tick` 的 attack 分支、`SPEED.attack`、`ACT_LABEL/ACT_COLOR.attack`、敌人悬停卡的「近战」行、工具表的 `atk/vsHard/kb`，以及**随之失去入口的 `hard` 标记**（`data/enemies.js` —— 没消费者就不留字段）。
**反向断言 `tool.pure`**（取代原 `melee.tools`）：工具表一旦又长出 `atk/vsHard/kb/dmg/dmgType/crit` 任一字段，`__check` 当场报“工具沾上了战斗数值（用户否决过的设计）” —— 防的是**它自己爬回来**。

## 5. 风险与不做清单

- **不做数值膨胀**：不靠"更多怪、更高血"制造难度（那是 inflation，只会更卡更烦）→ 难度来自**新行为 + 组合 + 信息**
- **组合失控**（数量与数值）：对策 = 有限槽位 + **燃料闸门**（越强越费，你的塔越强灯就越暗）+ `__lab()` 自动扫表 + 检测器上限断言。**不做 Noita 那样的无限组合**：本作是基地经营 + 有限波次（一晚只有 60s 蚀潮），无限组合会把平衡与可读性一起吃掉
- **移动战削弱基地**：对策 = 移动中射速减半、装卸要停下来按住 E、背负时燃耗 ×1.5、装载体可被啃掉真丢
- **塔"不动"的代码假设**（第 5 步专项）：塔的现有代码默认它不动 —— 占格/挡光/光照脏标记/寻路/存档/跨层六处都要专门回归，否则会出现"背着塔穿墙"或"存档后塔回到原地"这类诡异 bug
- **不绕过光照**：任何新敌人/新技能都不能让"光"失去意义（否则核心机制当场空掉）
- **不破坏帧预算**：每步都复测峰值夜 `frame.total`（现在 1.67ms，宽容 8ms）
- **不做 PVP/多基地/科技树重写**（超出范围，且会推倒现有手感）
- **深度优先于广度**：一个方位做透再换下一个；三个方位并行会互相踩数值
- 每一步做完都要：`__check` + `__srcCheck()` + 一晚真实帧 + 一局真实键鼠 E2E（B35 那套）+ localStorage 清理
