# 界面优化计划 · Deep-Light

## 目标

让玩家在 3 秒内看懂“我有什么、现在能做什么、为什么不能做”。界面用短句、状态色和固定位置表达，不把规则藏在长段说明里；所有物品与资源仍显示真实名称，交互不绕过账本。

## 已落实：UI-1 背包与交互一致性

- `I` 打开“背包”面板，面板与建造/夜行/研究/图鉴同样支持 Tab 轮换、搜索和 Esc 关闭。
- 背包显示容量、材料、工具；“丢 1 / 全丢”把物品放在脚边，仍经过存储账本，可重新拾回，30 秒后消失。
- 容器面板继续负责“容器 ↔ 背包”搬运，两个界面的容量数字都实时刷新。
- 文案采用“结果 + 下一步”格式：例如“背包满了”同时告诉玩家先丢弃或建箱子。

## 后续分步

### UI-2 科技树（已落实）

研究分区现在以分层节点图展示：按前置深度分成“起点 / 第 1 层 / 第 2 层 …”，列间箭头表达推进方向，同层节点自然形成分支。每个节点标出前置研究，并用完成/可研究/锁定三种状态色区分；研究面板会自动加宽，长描述不再互相挤压。节点数据继续来自 `js/data/research.js`，搜索、分区切换和 Enter 确认保持不变。

### UI-3 工作站（已落实）

制造台、熔炉、自动熔炉现在使用统一的站点摘要卡：顶部显示“输入 → 产出”和当前状态，中段保留配方与主要操作，底部显示缺料原因、预计时间和产出位置。站点面板自动加宽并允许说明换行，避免按钮与长文案挤在一起。

### UI-4 信息层级与可读性（已落实）

HUD 现在用图形化生命条与饱食条表达即时状态，低于阈值会变红；生命、饱食、光照、潮位仍保留数字。顶部在窄屏下自动收拢次要的夜间预告，长句提示继续放在下方情境提示行。

## 验收标准

1. 新开局按 `I` 能打开背包，至少能看到容量与初始物品。
2. 丢弃后 `state.res`、背包数量、掉落物三者一致；重新走到掉落物上能拾回。
3. `__check()`、`__check({roundtrip:true})`、`__srcCheck()` 全绿；菜单、新局、读档往返、回放四局面均通过。
4. `__watch(true,20)` 长跑无违规；不得新增依赖，不得改变资源守恒或光照规则。
