# W18-G · 远征与前哨补给闭环

> 目标：把已有的区块往返、现场建造和前哨结算收束成一条可读、可测、可扩展的流程。第一座前哨必须由玩家亲自携带材料，在目标区块建箱、点灯、补给，再决定是否派人驻守。
>
> 当前状态：G0 ✅；G1 ✅；G2 ✅；G3 ✅。本文是独立于已收口的 W17-F 的新小步计划。

## 设计边界

- 玩家可以自由深入或夜行；提示只提供信息，不强制返程、不自动传送。
- 不增加跨区块自动运输、营地投送、远程共享仓库、离线生产或无限资源。
- 前哨产出仍只进入目标区块本地容器；敌人总量仍由既有蚀潮波次预算约束。
- 所有资源准备度读取现有 `BUILD`、容器账本和 `ECOLOGY` 规则，不复制成本或消耗数字。

## 执行方案与工程量

本阶段按“先可读、再可玩、最后可回放”的顺序推进。每一步都独立验收，避免把远征提示、前哨生产和回放逻辑同时改动后难以定位回归。

| 步骤 | 交付物 | 主要改动 | 预估模型工作量 | 预计耗时 |
|---|---|---|---:|---:|
| G0 | 观测与数据地基 | `__expedition()`、契约断言、源文件清单、计划台账 | 4–6k tokens | 30–60 分钟 |
| G1 | 非强制远征与返程引导 | 远征 HUD 卡、回营方向、黄昏/补给软提示、一次性去重 | 8–12k tokens | 1–2 小时 |
| G2 | 现场建立前哨闭环 | 建箱→点灯→补给→派驻的状态投影与阻塞说明 | 12–18k tokens | 2–4 小时 |
| G3 | 有限往返回放与试玩矩阵 | 三条固定种子路径、5 日回放、前哨产出与返程边界断言 | 8–14k tokens | 1.5–3 小时 |
| 合计 | 可验证的远征/前哨首轮闭环 | 不含美术素材制作与新资源类型 | **32–50k tokens** | **5–10 小时** |

> 估算按一次实现、一次修复和一次浏览器回归计算；若发现存档兼容问题或旧档存在异常区块，按每个问题增加约 1–3k tokens。模型 token 是工作量参考，不是运行时消耗，也不作为功能验收标准。

### 推荐开工顺序

1. **G1 先做信息层**：只读现有区块、时间、背包和本地容器状态；不消耗资源、不改变移动、不改变敌潮预算。这样可以先验证远征决策是否清楚。
2. **G2 再接玩法闭环**：将“当地有箱、有人造光、当地有食物/燃料”作为前哨生产的可解释前置条件，所有扣除仍走现有账本入口。
3. **G3 最后做回放与调参**：把正式自由玩法和开发回放分离，使用固定种子比较守家、一次远征、驻守前哨三种策略，避免用回放工具反向改变正式规则。

### G1 的明确实现边界（已落地）

- HUD 只在非原点地表区块显示，内容保持一行短信息：回营方向、距黄昏/蚀潮的时间、当地食物/燃料、背包余量。
- 提示按“每区块一次；黄昏按每天一次”去重，优先级为：将入夜 → 无储物箱 → 无人工光 → 无食物 → 无燃料。
- 提示只调用现有短提示通道，不弹窗、不锁输入、不自动传送；返回营地后 HUD 自动隐藏。
- 只读检查当前区块，不扫描未加载区块，不创建新资源、不写入生产结算。

G1 实现拆分为 `data/expedition.js` 的文案/冷却契约、`systems/expedition.js` 的当前区块只读摘要、`main.js` 的 HUD/提示接线，以及 `index.html`/`css/style.css` 的状态卡。提示去重保存在会话态，不写入存档；新局和读档都会清空去重缓存。

### 每步统一验收门槛

- `__check()`、`__check({roundtrip:true})`、`__srcCheck()` 全部通过；新增断言不得空跑。
- 主菜单、新局、读档往返、`__replay()` 四种局面各跑一次；`__watch(true,20)` 后 `__testLog()` 为 0 类违例。
- 真实键鼠完成至少一次 `(0,0) → (1,0) → (0,0)`，确认远征信息出现、返回后消失，且不改变移动与战斗曲线。
- G2/G3 额外记录资源账本、前哨结算次数、敌潮预算和区块切换帧耗时；任何一项异常先停在当前小步，不跨步堆功能。

## G0 · 观测与数据地基 ✅

已完成：

1. 新增 `js/data/expedition.js`，固定观测契约版本、原点坐标和报告字段顺序。
2. 扩展 `__expedition()`：
   - 当前区块、群系、发现/持久化/活跃区块；
   - 玩家背包容量、占用、背负结构体造成的容量变化；
   - 储物箱与灯柱的现场建造准备度，缺少的材料逐项列出；
   - 当前区块本地容器、库存、空位、食物、燃料与有效人工光；
   - 前哨结算次数、产出、需求、阻塞原因与告警数；
   - 返回原点的方向、距离和是否已在营地。
3. 新增 `expedition.spec` 断言，锁定版本、原点和报告 schema；未改变玩法状态、账本或存档格式。

## G1 · 非强制远征与返程引导

- 首次进入非原点区块、黄昏临近、补给不足或生命偏低时显示一次性短提示，并使用 18 秒事件冷却避免刷屏；不在本步重复造一套战斗伤害规则。
- HUD 增加紧凑远征卡：营地方向、天黑剩余时间、食物/燃料/背包余量和前哨准备检查。
- 复用已有出口箭头，远端时突出回营方向；不把远征变成强制任务链。

验收：玩家能在相邻区块判断回营方向和缺少的补给；不改变移动、战斗、资源和蚀潮曲线。

## G2 · 现场建立前哨闭环

- 明确显示“当地建储物箱 → 点燃人工光 → 把食物/燃料放进当地容器 → 派拓荒者”的顺序。
- 无容器、无光、缺食物、缺燃料、满仓分别报告可执行原因；不把产出自动搬回营地。
- O 面板、背包和前哨观测共用同一份本地状态，不新增专用前哨建筑。

验收：相邻区块可手动建立箱+灯+补给前哨，派人后才产生有限本地产出；四类阻塞原因均准确可见。

### G2 实现与验收记录 ✅

- `outpostReadinessOf()` 只读取当前区块的容器、有效人工光、食物/燃料库存和拓荒者目标；不扫描未载入区块，也不复制账本扣除逻辑。
- 远端 HUD 改为 `前哨 N/4`，背包面板与 O 面板共用同一组五步状态卡：储物箱、人工光、食物、燃料、派拓荒者；状态通过 `data-live` 原位刷新，不重建整块面板。
- 完成 `(0,0) → (1,0)` 实测：远端建成储物箱与人工光、补入食物/燃料后由 `0/4` 变为 `4/4`；点击“派往此区块”后第五步变为已完成。
- 将成员切为“采掘”并返回营地后，远端区块低频结算从 `ticks=3` 继续到 `ticks=7`，本轮报告 `完成 1 次远端采掘`，目标箱新增 `vine=1`；玩家背包未被远程自动搬运。
- 返程后 HUD 自动隐藏；远端仍保持本地库存与驻守状态，证明结算只在区块离屏时运行，当前玩家区块不重复结算。
- 将当地箱填满后，状态卡保留 `4/4` 准备度，同时显示 `当地储物箱已满 · 先清空`；满仓不会被误报成缺箱，也不会触发自动搬运。

统一回归：主菜单/新局/存读往返/回放均 `__check()` 78/0；`__srcCheck()` 87 文件/0；`__watch(true,20)` 后 `__testLog()` 为 `共 0 类`。本次 `__perf()` 观测 `frame.total avg=1.04ms`，低于 16.6ms 帧预算（样本峰值 22.4ms 作为开发机偶发尖峰记录，不宣称为性能门槛通过）。

## G3 · 有限往返回放与试玩矩阵

- 将开发用 `expedition` 回放改成有限状态：准备 → 单次相邻区块 → 有限探索/落点检查 → 日落或补给阈值返程。
- 不改变正式游戏自由度；旧 F4 的持续外漂数据保留为历史压力样本。
- 固定种子 `4242 / normal / 5 天` 重新记录守家、一跳远征、现场落箱驻守三条路径。

验收：远征回放不越过一个相邻区块；前哨只有在当地容器和补给成立时产出；性能、存读和波次预算不回归。

### G3 实现与验收记录 ✅

- `POLICIES.expedition` 已从“持续向外推进”改为开发回放专用的有限状态：`prepare → outbound → explore → return → done`。它只在固定种子回放中生效，正式游戏仍可自由探索。
- 远征边界集中在 `data/expedition.js`：第 160 秒后出发、260 秒或补给/生命阈值触发返程，最多记录 1 个非原点区块；回放结果新增 `expedition.phase / remote / visited / returnDay / outOfRange`，可直接审计是否越界。
- 固定种子 `4242 / normal / 5 天` 守家回放：死亡 `1`、最低血 `2`、击杀 `156`、食物 `77`、燃料 `0`、蚀痕 `2`、最高光压/挑战 `18 / 1.48`，区块保持 `(0,0)`。
- 同种子有限远征回放：死亡 `0`、最低血 `100`、击杀 `96`、食物 `41`、燃料 `336`、蚀痕 `2`、最高光压/挑战 `0 / 1.00`；路线报告 `phase=done`、`remote=(1,0)`、`visited=[(0,0),(1,0)]`、`returnDay=1`、`outOfRange=false`。同种子重复运行路线报告完全一致。
- 现场前哨五日实测：真实建箱/点灯/补给、派拓荒者采掘并返回营地后，远端完成 `164` 次结算，目标箱库存为 `vine=43、fuel=9`；最终因当地食物不足暂停，未自动搬运回营地，远端告警 `0`。
- G3 长跑性能：`frame.total avg=1.249ms`、样本峰值 `10.2ms`、约 `121.5 FPS`；低于 16.6ms 帧预算。服务端保持 `py -3.12 serve.py 8000` 运行。

统一回归：主菜单、新局、存读往返、回放后 `__check()` 均为 `78/0`；`__srcCheck()` 为 `87 文件 / 0`；`__watch(true,20)` 后 `__testLog()` 为 `共 0 类`。G3 不改变正式自由探索、蚀潮敌人预算或跨区自动运输。
