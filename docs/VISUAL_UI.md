# E 视觉与交互重制计划 · W16-E

> 目标：从“可运行的原型界面”升级为耐看、直白、可操作的独立游戏界面。参考的是《环世界》式的**信息密度、可读性和操作节奏**，不是照搬其美术或 UI。
>
> 状态：**V0–V7 已落地。** 本轴将重做视觉语言与交互模型；既有 UI-1～UI-4 保留功能，但不视为最终品质。

## 核心判断

当前问题不在“功能少”，而在“视觉没有分层”：人、拓荒者、蚀兽、工具、交互热点都接近抽象圆形/色块；紫绿高饱和色同时争夺注意力；面板像开发工具而不是玩家操作界面。

重制原则：**地图让玩家读空间，HUD 让玩家读危机，面板让玩家做决定，角色让玩家记住人。** 同一时刻只允许一个层级抢第一注意力。

## 美术方向：深渊营地像素戏剧

- 视角：保留现有顶视角与 16px 基准格，不改世界坐标、不引入复杂骨骼动画。
- 风格：Q 版 16-bit 像素人 + 低饱和地形 + 极少量高价值辉光；轮廓清晰、材质简化、功能一眼可辨。
- 主色：石墨黑、深蓝灰、冷苔青、岩土褐；暖白/琥珀只给火与人造光；紫色只给蚀潮、蚀痕与高危敌对物。
- 色彩纪律：绿色不再承担“所有可交互物”，紫色不再承担“所有特效”。同类信息使用形状、图标、明暗和边框共同表达。
- 光照：程序化光照继续是世界核心；所有像素素材必须以局部固有色绘制，最终仍受现有光照和阴影叠加。

## 角色与生物视觉规格

### 人类：玩家与拓荒者

首版使用 **24×24 像素四向静态角色集**，不做行走帧：

| 项 | 规格 |
|---|---|
| 方向 | 前 / 后 / 左 / 右四张，左右可镜像但工具手与包袱可保留差异 |
| 读法 | 头部、躯干、双脚、手持工具、背包五个大形；不画小脸细节 |
| 区分 | 玩家有白边领灯或披风记号；拓荒者用职业主色 + 个人头饰/包袱/发型轮廓 |
| 状态 | 受伤、饥饿、倒地、背负、夜班用轮廓/小标记表达，不做整套换皮 |
| 职业 | 矿工镐、营造锤、机工工具包、守望提灯、行医肩包；与拓荒者轴共用数据 |

玩家与拓荒者都必须保留“手上正在做什么”的剪影：镐不是小方块，而是可见的斜向工具；提灯、枪、背负结构也应有不同轮廓。

### 蚀兽

敌人从圆形改为不同的动作剪影：芽 = 矮小爬行、壳 = 宽甲低伏、蛾 = 翼展、枭 = 上方掠影、盲兽 = 长身尖棘、核心 = 大型地貌。首版同样不需要逐帧动画，但要有朝向、受击闪白、移动拖影和攻击前摇提示。

### 地形与建筑

- 地形只做低对比底纹，矿脉、藤木、遗迹、潮穴用轮廓和材质区分，而非靠整块荧光色。
- 建筑采用“底座 + 主体 + 工作状态 + 光照层”四层绘制；熄灭、损坏、施工、满载应有独立剪影。
- 光源的火焰、灯芯和有效光域必须一致，禁止出现“看起来亮却不照明”的假反馈。

## 信息架构与交互模型

### 1. HUD：只保留即时危机

顶部 HUD 固定为三组：

| 左侧：生存 | 中央：时局 | 右侧：战术 |
|---|---|---|
| 玩家生命 / 饱食 / 伤势 | 昼夜环、蚀潮阶段、今晚主题 | 燃料、光压、下一波、撤离提示 |

- 数字只做精确读数；平时先读条形、图标和状态色。
- 光压变成可理解的刻度：低 / 稳定 / 吸引，而不是孤立数字。
- 生命危险、拓荒者倒地、建筑受袭可进入中央短事件条，但不得把所有提示都挤到同一行。

### 2. 世界交互：所见即所得

- 鼠标悬停显示“对象名 + 关键状态 + 一个主要动作”，而不是长说明。
- 左键只做主动作，右键只做次动作/取消，`E` 只做近距离明确交互；快捷键显示在按钮和悬停卡上。
- 地块/建筑的可建、不可建、危险、超距离状态使用不同边框形状与半透明填充，不只换颜色。
- 选中一个对象后出现环形或条形“上下文动作条”，把常用动作放到鼠标附近，减少记忆键位负担。

### 3. 面板：从长列表改为决策卡

- 右侧面板保留为“详情与管理区”，宽度可扩展；绝不再用窄栏塞大段文字。
- 制造、研究、存储、拓荒者、前哨统一用：标题区 → 状态摘要 → 可执行动作 → 代价/风险 → 细节折叠。
- 建筑和配方使用卡片：图标/小像素图、输入→输出、耗时、燃耗、缺少项；一张卡只回答一个决定。
- 科技树保持节点图，但增加缩放、拖拽、节点悬停解释和“下一项推荐”路径；连线必须在节点下方，文字不可压线。

### 4. 键鼠与手柄友好

- 所有可点击 UI 都有悬停、按下、禁用、键盘焦点四种状态。
- `Esc` 的关闭顺序固定：子菜单 → 面板 → 暂停；不会误触打开/关闭多个层。
- 热键不只藏在 H：常用按钮显示键位，小地图、建造栏、任务栏提供鼠标直达。
- 为未来手柄留“焦点顺序”和大按钮间距，不在本轮强制做手柄适配。

## 素材管线与协作方式

- 不依赖外部大型美术包：程序化渲染先落实规格与占位，PNG/SVG 像素素材可后续逐张替换。
- 首批角色资产优先级高于菜单插画：人是玩家持续观看最多的对象。
- 建议规格：人类 24×24 四向静态集；蚀兽 24×24 至 48×48；建筑 32×32/48×48；UI 图标 16×16 或 SVG。
- `assets/PROMPTS.md` 中“行走像素小人暂不用”的旧结论被本计划替代；后续实现时新增对应 sprite key 和清单，不直接覆盖已存在的图鉴资产。

## 固定约束

- 不引入 UI 框架、图形引擎或构建工具；仍使用 Canvas 2D + 原生 DOM。
- 视觉效果不能掩盖光照、建造判定、寻路或资源守恒的真实状态。
- 先做清晰的静态像素姿态和反馈，再考虑动画；拒绝“为了动而动”。
- 所有玩家可见文字必须遵守 `docs/COPY.md`；每一步同步本计划、`HANDOFF.md`、`docs/BUG_HUNT.md` 与 README。
