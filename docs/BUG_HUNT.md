## 0. 原则（先说清怎么干，避免又变成"越修越乱"）

| 原则 | 具体做法 |
|---|---|
| **检测先于修复** | 每步先写/跑检测器，得到**基线**（当前已知问题清单）；改完再跑一次对比 —— 这样既知道修好了没，也知道有没有打坏别的 |
| **白名单而非静默** | 已知但暂不修的违例登记进台账并**显式标记**，避免噪声把新问题淹掉 |
| **一个不变量 = 一条可复算的断言** | 不写"应该没问题"这种话；每条违例都要能打印出**现场数据**（哪个实体、哪个坐标、哪个数） |
| **修一个 bug 补一条断言** | 复现过的 bug 一律留下断言，防止复发（这次会话已经踩过 3 次"改 A 坏 B"） |
| **设计选择不算 bug** | 报给你时明确标注：这是**缺陷**还是**取舍**（例如"炉子空烧火种"是设计，不是 bug） |

### 本计划的四类"高发 bug 家族"（来自本会话的真实教训）

| 家族 | 本会话的真实例子 | 用哪一步抓 |
|---|---|---|
| **跨模块隐式依赖** | `panels.js` 里没有 `state`，拖拽落点直接 `ReferenceError` | 第 1、4 步 |
| **返回值语义反直觉** | `withdraw()` **返回 null 表示成功**；`lightFire` 里 `!withdrawOne()` 读起来像失败其实是成功 | 第 1、2 步 |
| **多系统抢同一个输入** | 站在炉边按 E 被旁边的藤木抢走（交互优先级） | 第 4 步 |
| **派生数据不同步** | `dry` 是旧值 / `liveSig` 少字段 → 面板数字停住 | 第 2、5 步 |

## 1. 现有资产（决定了这计划做得动）

- **体量**：64 个 JS 文件 ≈ 9.3k 行 JS；最大几个：`main.js 1664` · `ui/panels.js 1115` · `systems/render.js 1105` · `entities/worker.js 667` · `ui/screens.js 491`
- **零构建、零依赖**：纯 ES Module + 原生 Canvas —— 适合**在浏览器里直接跑断言**，不需要搭测试框架
- **已挂 70 个调试句柄**（`window.__*`）：`__state/__steps/__spawn/__place/__finish/__give/__take/__store/__mind/__blight/__overlap/__perf/__stress/__saveSlot/__loadSlot/__newGame/__resolve/__sight…`
  → **检测器只是把这些句柄组合起来**，基本不用碰游戏代码
- **确定性推进**：`__steps(n, dt)` 可以在暂停状态按固定步长推进模拟 —— 长跑与边界扫描都能做到不依赖真实帧率
- **真键盘/真鼠标**：Playwright 可打真事件（`page.keyboard` / `page.mouse` / `dragAndDrop`），负责"只有真输入才能暴露"的那部分
- **当前缺口**：`docs/` 下没有测试记录；没有不变量断言；没有 bug 台账 → 本次补齐
- **新增（第 0 步已完成）**：
  - `js/dev/selftest.js` —— 不变量检测器（29 项运行时/数据断言 + 7 项源码审计），挂在 `__check/__watch/__baseline/__only/__testLog/__srcCheck`
  - `js/dev/filelist.js` —— 由 PowerShell 生成的 `js/` 文件清单（源码审计要能 `fetch` 自己）
  - 控制台用法：`__check({includeKnown:true})` 看全部（`ran`=项目数）· `__baseline()` 冻结已知 · `__watch(true,20)` 长跑期间每隔 20 帧体检 · `__testLog()` 看累积违例（**末尾一行“共 N 类”要减掉**）· `__srcCheck()` 扫源码（返回 `{ok, files, fails:[]}`）

## 5. 附：为什么这次能比"一个个手点"更彻底

1. **手点的最大盲区是"状态组合"**：人只会试几种情形，矩阵扫描会把 `建筑 × 动作 × 前置状态` 全跑一遍
2. **手点的第二个盲区是"时间边界"**：人不会盯着第 300 秒那一刻，机器可以逐秒扫
3. **手点的第三个盲区是"长跑"**：人玩不到第 10 天，机器可以 60 倍速跑完
4. **写下来的断言会一直在**：以后每次改代码，`__check()` 一跑就知道有没有打坏旧功能 —— 这才是"小 bug 太多"的根治办法
D94. **V7 最终 E2E 的坐标系误判（2026-09-17）**：首次用 `__screenOf()` 返回的客户端坐标直接喂给 `__rclick()`，导致熔炉看似“没反应”；根因是 `__rclick` 接受画布内部坐标，而真实 CDP 鼠标接受客户端坐标。修正为按 `canvas.getBoundingClientRect()` 换算后，真实右键点火与面板流程通过。此后测试先确认坐标域，再判定交互失败。
D95. **测试接口名称误用（2026-09-17）**：回归脚本把 `__settings`（观测对象）当成函数调用，造成一次 TypeError；游戏状态未被破坏，随后直接在新局继续完成 `__check`/回放/源码审计。以后先用 `typeof` 或 `__settings()` 的实际导出约定确认调试口形态。
D96. **区块出口反向闪烁（2026-09-17）**：切区块后落点 `m.w-1.5 / 1.5` 仍在对侧 `EXIT_TRIGGER=1.6` 触发带内，下一帧会立即反向切回；改用数据表中的 `EXIT_SPAWN_INSET=3.5`，120 步只记录一次区块变化。
D97. **表面外围岩壁阻断出口（2026-09-17）**：`genMap()` 仍铺满四条边界岩壁，与开放区块设计冲突；移除表面边界铺设，深层洞穴边界保持不变。
D98. **满箱整格闪红（2026-09-17）**：储物箱满时渲染器额外覆盖整格红色，导致箱体辨识度下降；保留底部容量条红色，移除整格脉冲覆盖，侧栏仓储行也保持稳定色。
D99. **蚀潮候选排除完全黑格（2026-09-17）**：`spawnOne()` 使用 `light >= 0.01` 下限，单灯照明时所有灯外格都是 0，导致整夜 0 怪；保留“必须有人工光源”的区块门槛，允许 `light=0` 的最弱边缘作为入侵点。
