# 生存深挖计划 · W15-B（生存 / 建造 / 远征）

> **状态：第 0–7 步已验收 ✅；第 8 步 UI-1 背包、UI-2 科技树、UI-3 工作站、UI-4 HUD 已落地。**
> 前置：[HANDOFF.md](../HANDOFF.md)（当前基线）、[COMBAT.md](COMBAT.md)（分步纪律范本）、[BUG_HUNT.md](BUG_HUNT.md)（检测器与台账）。
>
> 本轴不把“生存”理解成多几根永远下降的条，而是让玩家每一天回答三件事：**谁有资格出门、今晚哪一段领地值得守、失败之后还拿得回什么。**
> 它要把现成的光照、夜行指令、心志、容器、工具、工地、塔和多层世界接成一条循环；不做一套与战斗、建造各玩各的饥饿模拟器。

## 0. 结论与边界

### 0.1 本轴交付的玩家循环

```
白天：吃饭/疗伤 → 采集与施工 → 选择扩张、休整或囤粮
黄昏：决定谁守夜、谁夜采、谁休整；确认哪条退路和哪个储物点可用
蚀潮：光路与工事保护人、食物与远征补给；死亡会留下可追回的损失
黎明：回收遗落物、修复防线、照料疲惫者；让可再生资源回到合适的地块
远征：穿过区块边界，找到有限的辉髓与新的地形机会，再带着物资回家
```

核心取舍不是“能否活下去”，而是：

| 现在已有 | 本轴补上后 |
|---|---|
| 食物主要由拓荒者自动吃；玩家没有主动恢复 | 食物是**口粮 / 热食 / 招募**三选一；玩家与拓荒者都能从同一账本取用 |
| 玩家死亡 = 回营、燃料减半、整夜清空 | 死亡是一次**撤退**：留下一份遗落物、失去当晚阵地时间，仍有可救回的路径 |
| 结构只有木墙 | 工事要承担“堵、绕、通过、修、撤”的空间语言，而不是多几种不同血量方块 |
| 工具主要是采得更快 | 工具扩展为有限的**行为开关**：开石、施工、维护、地形整理；不变成装备词条池 |
| 节点采空即消失 | 辉髓等战略矿保持有限；食物与生物质可在明确条件下再生，形成可管理但不通胀的循环 |
| 一张 96×72 地图四周封死 | 保留单区块性能模型，改用确定性相邻区块实现远征；不把全世界塞进一个超大数组 |

### 0.2 本轴的设计律

1. **光仍是生命线。** 床位、热食、前哨、可再生农林都要与安全光区发生关系；不能用“睡一觉满血”绕过光和燃料。
2. **资源不凭空变多。** 所有获得仍经 `deposit`，所有消耗仍经 `withdraw`；再生只能是有来源、有上限、有时间的转换，不能把辉髓变成无限货币。
3. **失败有代价，但不是读档税。** 玩家死亡不得永久锁死工具链，也不得清空一夜的全部威胁作为免费跳关。
4. **工具是动作，不是词条。** 每一件工具必须打开一种新动作或空间关系；不做 +12% 暴击、耐久度磨损、随机品质。
5. **区块扩张不是放大地图。** 活跃区块仍维持约 96×72 格和现有光照/寻路预算；远处区块序列化为状态，不在每帧更新。
6. **生态另立 C 轴。** 本轴只建立资源循环、地块条件与区块接口；不在这里并行加入完整动物作息、食物链、光压反噬或大量新敌人。

### 0.3 明确不做

- 不做同时存在的体温、湿度、疾病、疲劳、口渴五条衰减条；本轴只先做可读的“饱食 / 休整 / 伤势”。
- 不做无限刷怪、无限辉髓、矿物自动无限再生；地表约三天后仍应鼓励下潜与远征。
- 不做近战武器树。W14-A 已定：工具是生产件，黑暗自保由辉光棒、光爆、结构装载体与防线承担。
- 不做真正无缝的大世界、全图寻路或每帧更新所有区块；那会直接吃掉 16.6ms 预算。
- 不重写研究树、存档系统、战斗载荷；新增锁和字段必须向后兼容地接入现有体系。

## 1. 现状盘点（代码，而不是印象）

| 面 | 已有地基 | 缺口 / 风险 |
|---|---|---|
| 拓荒者饥饿 | `worker.hunger` 0–100；低饱食会掉士气，归零有 25 秒缓冲后掉血；会自动从容器取 `food` | 玩家没有对应的进食入口；“食物”对玩家是侧栏数字而非决策 |
| 治疗 | 拓荒者在光照 >2.5、饱食 >40 时缓慢回血；热食与心志已有概念 | 玩家只有死亡后满血，没有主动、可控、会消耗资源的回复路径 |
| 玩家死亡 | `handleDeath()` 将玩家移回营地、清空敌人、夜战跳到黎明并扣除 50% 燃料；背负结构会在死亡点卸下 | 代价集中在燃料，且“整夜清怪”会把死亡变成最优撤退按钮；背包/手持工具的风险不充分 |
| 建筑 | 工地/工期、占格、挡光、拆除返还、储物、塔、光路全部成熟 | `struct` 分类只有木墙；缺少“能控制路径但不等于又一座墙”的空间语言 |
| 工具 | 石镐、斧、镰、锤、辉光棒均为真物品且会进容器/存档 | 生产链停在采集加速；没有维护、门控、地形整理等工事动作 |
| 资源 | 辉髓、藤木、石头等节点经 `nodeAmt` 采空后变地面；农田可持续产食物 | 除农田外没有可再生闭环；若直接让矿脉刷新会抹掉下潜和探索的节奏 |
| 地图 | 地表固定 `genMap(96,72,seed)`；鼠标、寻路、光照、迷你图和存档均以单一 `state.map` 为中心 | 四周边界和大量模块假设一张活跃地图；“删一圈岩壁”本身不足以提供世界状态、生成与存档模型 |

**重要结论：** 地图扩张必须是本轴的后段“区块远征”子轴，不能与饥饿、死亡、结构在第一步同时动。先把人在一张图上“活得有代价”做好，才值得扩大他们能去的地方。

## 2. 判据先写死

| 维度 | 目标 | 可复算判据 |
|---|---|---|
| 玩家生存 | 玩家能主动使用现有食物恢复，并能选择更贵但更安全的热食 | 空腹、受伤状态下：口粮与热食各自的资源差额、HP/饱食/心志差额完全等于数据表；0 食物/0 燃料不得白嫖效果 |
| 人员调度 | “夜采 / 守卫 / 休整”会影响次日可用劳力，但不产生多余条目轰炸 | 标准局第 1–3 天至少出现一次“夜间收益 vs 次日效率”的可观测选择；休整后状态恢复，透支有明确且有上限的代价 |
| 死亡 | 死亡不再是免费清夜，但仍可挽回、不会软锁 | 玩家死亡后遗落包存在且可回收；营地保留基础工具链；同种子下“主动封灯撤退”在资源损失上优于无准备死亡 |
| 工事 | 至少形成三种不同空间决策：封路、可控通行、延缓/修补 | 同一入口用墙、门、路障三种组合，敌人到营地的路径长度/通行状态/维修成本不同；所有占格与寻路断言为 0 违例 |
| 工具 | 每件新增工具对应一个非战斗新动作 | 工具表、配方、站点、交互、存档、UI 与检测器交叉一致；失去工具仍可通过营地保底路径重建 |
| 再生 | 食物/生物质可持续，战略矿有限 | 10 天回放中再生资源从不超声明上限；辉髓/母髓/遗迹不会因再生逻辑增加；挂机不会因自动再生变成无成本永动机 |
| 远征 | 区块边界可探索、可存读、可回家，且不劣化活跃帧 | 固定 `seed + chunkX + chunkY` 生成相同区块；往返后建筑、容器、节点、蚀痕、遗落包逐项一致；峰值夜 `frame.total ≤8ms` |
| 联动 | 生存系统必须改变战斗前、战斗中或战斗后的决策 | 标准回放的“守家 / 远征 / 休整”三种政策在至少两项中不同：最低血、死亡、击杀、资源、人员状态、封灯日 |

统一回归门槛：每步都须在**主菜单 / 新局 / 存读往返后 / replay 跑过数天后**跑 `__check()`；`__srcCheck()` 0 失败；真实键鼠跑本步路径；`__watch(true,20)` 记录 0 类新违例。

## 3. 分步走

### 第 0 步 · 生存观测台与数据收口（零玩法变化）

**只搭台，不改行为。** 把分散的玩家恢复、拓荒者饥饿、死亡燃料损失、建筑耐久、节点上限与再生预留参数放入 `js/data/survival.js`；现有行为读表但数值一字不动。

- 新调试口 `__survival()`：玩家 HP/计划新增的饱食与休整占位、全队饥饿/伤势、食物与燃料账、遗落包、当前区块坐标、可再生节点统计。
- 新调试口 `__expedition()`：只读当前区块、已发现相邻区块、跨区块持久状态数量；第 0 步可先返回单区块基线。
- 断言：`survival.consts`（所有秒数/比例合法）、`survival.ledger`（进食/死亡仍走账本）、`node.bounds`（节点量在 0..max）、`world.active`（活跃地图尺寸与光照数组一致）。

**判据：** `__survival()` 能完整复现当前行为；原 63 项断言全部绿，新增断言也绿；`__replay({seed:4242,diff:'normal',days:3,policy:'home'})` 的既有曲线不变。

### 第 1 步 · 玩家吃饭、疗伤与“热食不是回血药”（最小生存闭环）

新增玩家的**饱食**，但不新增复杂食谱树。使用同一份 `food`：

| 动作 | 条件 | 资源代价 | 效果 | 决策 |
|---|---|---|---|---|
| 口粮 | 玩家任意安全时按 `Z` 使用 | 食物 ×1 | +30 饱食、+10 生命 | 出门前保命，但会与招募抢食物 |
| 热食 | 营地火/已点燃炉旁按 `Z` | 食物 ×1 + 燃料 ×1 | +40 饱食、+28 生命、解除一层伤势 | 花燃料把人恢复到能守夜的状态 |
| 拓荒者进食 | 保留当前自动行为 | 食物 ×1 | 与当前等效，后续统一显示原因 | 玩家不能靠抢食让 AI 饿死而无提示 |

- 玩家饱食下降只与远征、受伤恢复、夜间行动有关；**不做持续口渴条**。
- 受伤采用 0–2 层离散状态（擦伤 / 重伤），而不是第二根长血条；当前会增加饱食消耗，热食每次移除一层，休整的完整联动留到第 2 步。
- 交互必须让路给现有 E/右键优先级：无目标时才可吃；输入框、面板内不得触发。
- 所有玩家可见文案实施前先依 `docs/COPY.md` 校对。

**判据：** 食物 3→2 时口粮各字段按表变化；热食食物/燃料各 −1 且只有在有效火源旁成功；无料不改变任何状态；存读保留玩家饱食与伤势；真键鼠从“受伤 → 吃口粮 → 热食”走完且 0 pageerror。

### 第 2 步 · 休整、夜班与床位（人手成为夜战资源）

引入**休整位**，而非按秒下跌的疲劳条。新建筑“简易铺位”提供 1 个安全休整位；在光照与非敌袭条件满足时，玩家或拓荒者可进入休整。

- 夜采 / 守卫维修 / 巡逻 / 玩家深夜远征会累积有限的“透支”层；每层只影响次日工作效率与心志恢复，不直接扣血。
- 黄昏夜行面板明确显示：今晚指令会占用几名可休整者、已透支人数、可用铺位数。
- 玩家可在铺位或营地火旁主动休整；这推进**少量、可预期**的时间，不能用于无成本跳过整夜。
- 光照失效、蚀潮逼近或敌人进入安全半径时，休整自动中断并说人话。

**与战斗的联动：** 守卫能修墙、夜采能换夜髓、巡逻能少出怪，但都会消耗明天的施工/采集能力；“全员守城”不再永远是正确答案。

**判据：** 2 名拓荒者、1 个铺位时，休整位不超配；同一拓荒者透支层不超上限且存读不丢；守卫一夜与休整一夜在次日 `workerBuildMul`/采集产出有声明差异；蚀潮中不得进入休整；峰值夜新增逻辑 <0.05ms/帧。

### 第 3 步 · 死亡 = 可追回的撤退（不是免费跳夜）

在不做硬核永久死亡的前提下，重写玩家死亡的**损失分配**：

1. 死亡点生成“遗落包”，记录玩家背包、手持工具与可携带物；已有背负建筑仍原地卸下，不能借死传送。
2. 玩家回营时以低生命、受伤/透支状态苏醒；燃料损失改为数据表中明确的“营地救援消耗”。
3. 蚀潮不再无条件清空全体敌人。可保留当前“潮退到黎明”的容错，但敌人对建筑造成的结果、遗落包的位置与当晚未完成的防线必须留下；具体退潮规则只从 `SURVIVAL.DEATH` 一处读取。
4. 遗落包可由玩家或被指派的拓荒者在安全条件下回收；若跨天仍未取回，不是直接删除，而是转为带明确期限和风险的“失联物资”。

**软锁保护：** 开局/营地永远保留徒手采集和一条最低档工具重建路径；不允许把唯一石镐、唯一竖井权限和全部食物同时锁在不可达遗落包。

**判据：** 死亡后遗落包总物品数与死亡前背包/手持逐项守恒；回收后逐项恢复；不带背包死亡不生成空包；死亡、读档、跨层、区块切换均不复制遗落包；同一夜“封灯撤退”和“无准备死亡”各自成本能由 `__survival()` 列出且不相同。

### 第 4 步 · 工事语言：墙、门、路障与维护（结构不是更多血条）

只新增能产生空间选择的最小结构集：

| 结构 | 身份 | 与战斗的关系 |
|---|---|---|
| 木墙（保留） | 便宜、快速、可拆的临时封路 | 给第一夜争取施工与维修窗口 |
| 石墙 | 更慢、更贵、耐久更高 | 为深层/长期入口提供可靠瓶颈，不取代灯与塔 |
| 栅门 | 友方可开关、敌人受阻；关闭时算工事 | 让“回家路线”与“怪物路线”第一次不同 |
| 路障 | 可通行但显著减速、低耐久 | 让震荡塔、连锁塔、修理指令和撤退路径形成组合 |
| 简易铺位 | 第 2 步的休整位，弱结构 | 人员恢复必须占用受光、可被守住的空间 |

- 石墙/栅门/路障的成本、HP、工期、穿行和挡光属性全在 `data/buildings.js`；没有任何数值散落在系统中。
- 新增“维护”任务：守卫/玩家可修理受损工事，材料经账本扣除；不能在敌人贴脸时免费满血。
- 不做“自动防御墙”“无限升级墙”“一格万能堡垒”。工事的上限由入口、维修人手、燃料和敌人破墙行为共同决定。

**判据：** 每种结构在 occupied/walk/light/pathfinding 四张口径中一致；门开/关后路径立即重算且不把单位夹进实体；路障确实改变地面敌人通过时间、对飞行敌人无效；拆除、施工、存读、背塔移动、跨层均无重叠/幽灵占格。

### 第 5 步 · 工具链补齐：维护与地形整理（行为开关，非武器树）

在现有石镐、斧、镰、锤、辉光棒上，仅补两件有清楚职责的工具：

- **修缮钳 / 套件**：允许快速维护栅门、路障和受损工事；不增加战斗伤害，消耗明确的藤木/石料补件。
- **石铲**：整理“松散地块 / 菌床 / 可再生基质”，用于第 6 步再生系统的地块准备；不能挖出无限石头，也不替代石镐开岩。

实现前要先验证二者是否真的不可由石锤/徒手完成；若不能回答“它改变了今晚什么决定”，删掉而不是凑工具数量。配方仍由制造台产出，工具仍是真物品、仍会进容器和存档。

**判据：** 新工具没有 `atk` 或伤害类型入口；失去后可依基础配方重建；所有操作通过 `resolveInteract` 明确优先级，E 与右键不会抢已有采集/施工；工具表/配方/储物排序/图标/源码审计完全一致。

### 第 6 步 · 有上限的再生：菌床与藤木，不是无限矿井

资源分为三类，规则必须一眼可读：

| 类 | 资源 | 规则 |
|---|---|---|
| 有限战略资源 | 辉髓、母髓、遗迹 | 绝不自然再生；驱动下潜、远征与终局 |
| 受控再生资源 | 食物、藤木/生物质 | 必须由农田、菌床或准备过的地块产出；需要空间、时间与光/暗条件 |
| 地形资源 | 石头 | 来自岩壁/区块地形；仅在未来生态事件或新区域作为有限供给，不做定时刷新 |

- 幽菌田保持主食身份；新增“菌床/育藤地”作为生物质循环，而非把普通藤木节点直接刷回原处。
- 再生依赖可观测的地块条件（例如合适光照、未被蚀痕覆盖、间距、基质），并有区块级上限；玩家要决定把安全光给农田、把半暗边缘留给菌床，还是继续外扩。
- 敌人踩踏、蚀痕与工事保护在这里相遇：再生地块是经济目标，但不允许一夜清零造成不可恢复的死局。

**判据：** 10 天确定性回放中，受控再生总量不超过表中“地块数 × 周期产出”的理论上限；辉髓/母髓/遗迹增量严格为 0；不同光照/蚀痕条件下的生长差异按表复算；挂机对照仍会因饥饿、攻击或糟糕调度失败。

### 第 7 步 · 区块远征地基：跨越边界，而不是放大数组

这是用户提出“移除边缘岩壁、探索更多区域”的**纵切**，应在前六步稳定后实施。方案不是删除边缘后留空白，而是一个确定性区块世界：

```
世界坐标 (cx, cy) + 世界种子
        ↓ 确定性生成
96×72 活跃区块（唯一参与渲染、光照、寻路、AI）
        ↓ 边缘出口
相邻区块按需载入；离开后只保留序列化差异
```

- 第一个交付只做地表东/西相邻区块，再推广四方向；每个区块维持当前尺寸，边缘用可见“出口地形”而不是硬岩壁封死。
- 生成键必须只取 `worldSeed + cx + cy + biomeVersion`；同坐标必然同地形/节点/遗迹初始分布。
- 持久差异至少包括：建筑、工地、容器、节点剩余量、蚀痕、墓碑、遗落包、发现度与局部生态时钟。敌怪仍遵循既有“读档清夜”设计，不能无意变成离线刷怪。
- 区块通过“远征路标 / 前哨箱”与第 3、6 步连接：没有补给与回收路线就走太远，玩家会在死亡、负重和天黑时付出代价。
- 群系只先交付 2 种**规则差异清楚**的地表群系（例如藤木富集但视野破碎、岩层富集但可建地少）；完整生物作息和生态反馈留给 C 轴。

#### S08 实施约束（光源/活跃度/生产线）

- 区块不是“全世界同时运行”的数组：当前区块及其中存在玩家或存活拓荒者时才是**活跃区块**，执行 AI、蚀潮、光照、工事与生产；无人区块进入休眠，只保留地图、建筑、节点、容器、蚀痕与敌怪快照，不推进燃料、机器进度或离线产出。
- 夜间刷怪必须同时满足“区块活跃”和“存在人工光源”。太阳环境光不计入人工光；营地信标、燃料灯、手持灯等形成的光场才会产生夜间风险。候选点取当前人工光场的最弱边缘（允许 `light = 0`，即灯照不到的入口），没有任何人工光源的区块仍不刷怪。
- 地表区块出口为中心七格高、四格深的固定开放通道；载入旧区块时会补齐通道。跨区块落点距触发带至少 1 格，避免立即反向切换。
- 玩家进入出口走廊附近时，在走廊内侧显示对应方向的淡色脉冲箭头；离开走廊后自动隐藏，作为低干扰的探索引导。
- 玩家熄灯不是“清除战斗”的免费按钮：本轮已激活的敌怪仍保留，黎明照常消解；下一批只有在重新点亮并满足活跃条件后才会生成。跨区块时保存当前区块引用，返回后恢复同一份实体/建筑/节点状态。
- 第一个纵切交付四方向统一的数据接口，但内容只开放地表东/西出口；退出通道为边缘五格宽的确定性缺口，相邻区块由 `worldSeed + chunkX + chunkY` 派生，原点营地不会在远征区块重复生成。
- “有人看管”的生产线与区块活跃度绑定。未来的自动化核心、远程观察站若要让无人区块继续生产，必须作为明确的昂贵激活器接入，而不是偷偷加入离线结算。

**判据：** `seed=4242,cx=1,cy=0` 的地形签名跨重载一致；A→B 建造/采集/放遗落包→A→B 后逐项一致；区块边缘没有越界寻路、光照数组错尺寸、重复营地或重复天然竖井；活跃区块峰值夜仍 ≤8ms，存档大小与已修改区块数近似线性而不是全世界展开。

### 第 8 步 · 生存界面：背包、站点与研究树（信息必须能做决定）

UI 不作为“顺带美化”，而是每项生存决策的可见接口；它在对应系统数据稳定后单独实施，不能与机制改动混批。

| 界面 | 现有问题 | 目标交互 | 不做什么 |
|---|---|---|---|
| 玩家背包 | 只能在容器旁查看背包，不能随时核对携带物、丢弃或为远征整理 | `I` 打开轻量双区界面：随身物 / 装备；可丢弃到地面、查看重量/容量、在容器旁转为双栏搬运 | 不做无限背包、格子 Tetris、自动整理迷你游戏 |
| 存储与站点 | 容器、熔炉、制造台等各自有面板，但信息密度与动作层级不一 | 统一“库存 → 配方/动作 → 结果/原因”的结构；所有消耗在确认前显示来源与差额 | 不把每个方块做成独立全屏菜单 |
| 研究树 | 当前按分区列表展示，前置与分支的空间关系弱 | 提供可缩放/拖拽的研究图谱视图；节点连线读真实前置，知识锁与普通研究视觉区分，仍保留搜索与键盘路径 | 不重写研究数值或把未知知识全部提前剧透 |
| 生存 HUD | 食物、伤势、夜班、遗落包、远征补给会分散在侧栏/提示中 | 只在“需要决定”时显示紧凑状态卡与下一步；预警必须说明原因和可执行解法 | 不增加常驻十条进度条 |

**判据：** 背包、容器、工作台、研究图谱四条路径均有真键鼠 E2E；输入框聚焦时全局热键让路；所有丢弃/搬运/制造的账本前后差额可复算；研究图每条连线都能追回 `RESEARCH.req`，不存在幽灵节点；极窄窗口（360×640）无横向溢出。

### 第 9 步 · 生存回放、调参收敛与真实远征 E2E

新增但不替换 `home`/`idle` 的回放政策：

- `rest`：优先保持休整与食物储备，作为低风险对照；
- `expedition`：带补给跨一个区块、采有限矿、在黄昏前回营；
- `panic`：不修工事、不回收遗落包，验证失败不是被系统悄悄抹平。

#### 首轮基线（seed 4242 / normal / 5 天）

| 策略 | 死亡 | 最低玩家 HP | 击杀 | 结束食物 | 结束燃料 | 蚀痕 |
|---|---:|---:|---:|---:|---:|---:|
| rest | 0 | 44 | 63 | 86 | 0 | 4557 |
| expedition | 0 | 100 | 3 | 60 | 0 | 6013 |
| panic | 1 | 4 | 0 | 0 | 1 | 3809 |

解读：`panic` 确实会死，说明放弃生存动作有代价；`rest` 能守住营地但燃料在第 5 天归零，后续需验证自动化与燃料循环；`expedition` 当前主要验证跨区块移动压力，战斗参与度偏低，暂不据此调低敌人强度。

**最小验收表（固定种子 4242、标准、至少 5 天）：**

| 政策 | 必须看见的结果 |
|---|---|
| rest | 人员伤势/透支受控，但资源/远征收益较低 |
| expedition | 获得远征收益，但有更高补给、风险或恢复成本 |
| panic | 死亡或领地损失显著增加，不能靠自动再生和死亡清夜白给活过 |

真键鼠覆盖：玩家吃口粮/热食 → 安排夜班 → 建造并开关栅门 → 被击倒并回收遗落包 → 准备菌床 → 穿越区块边缘 → 存读后返回原区块。每个动作都有资源差量、浮字/提示与无异常证据。

## 4. 需要先拍板的设计决定

这些决定会改变范围，动代码前应由作者确认：

1. **玩家饱食的表现：** 推荐只在低饱食/受伤时显示，平时不再给 HUD 加一根常驻条；它服务于“出门前吃一口”，不是日常打卡。
2. **死亡后的蚀潮：** 推荐“潮退到黎明但不撤销已经对建筑/物资造成的后果”，保留容错，取消免费清空一夜战果的收益。
3. **石墙是否挡光：** 推荐石墙与木墙都挡光，逼玩家为射界、门洞、棱镜与防线形状做选择；不要做可无代价透光的绝对堡垒。
4. **再生资源的光照方向：** 推荐主食幽菌田要亮、藤木/菌床偏半暗，形成同一块地的光预算竞争；具体阈值后置到第 6 步基线测量。
5. **区块世界的规模：** 推荐先做无限坐标、只激活一块的模型，而不是先限制 3×3；内容上先只放两个相邻群系，避免生成内容爆炸。

## 5. 风险与防线

| 风险 | 防线 |
|---|---|
| 生存变成繁琐家务 | 休整用离散层与床位，不做每秒疲劳；每项资源消耗都能改变夜战或远征选择 |
| 玩家死亡导致软锁 | 遗落包可回收、基础工具链常驻、所有损失都有上限与明确 UI |
| 新结构形成无敌龟壳 | 墙挡光、门有开关时机、敌人保留破墙/飞行/远程行为，维修消耗人手与材料 |
| 再生让经济通胀 | 只再生食物/生物质，声明上限并由断言防矿物重生；挂机曲线必须仍失败 |
| 区块改动牵动太广 | 先建立 `world/chunks.js` 的单一入口，逐模块迁移并为 light/path/save/minimap 做专项回归；不在同一批加新群系和生态 AI |
| 存档膨胀或旧档损坏 | 只存已修改区块 diff，旧档默认 `(0,0)` 单区块；每加字段立即跑 roundtrip fuzz |
| 战斗轴被稀释 | 每一步跑 `__forecast/__wave/__dps` 与标准回放；生存调参不直接偷偷改敌人 HP、波次乘子或塔伤害 |
