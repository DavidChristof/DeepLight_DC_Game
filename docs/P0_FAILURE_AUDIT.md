启动 `py -3.12 serve.py 8000`，在右侧浏览器打开 `http://localhost:8000/__p0_failure_audit.html`，点击“运行审计”。无需作者存档、R4/R6检查点、npm或测试框架。

夹具每项从seed4242/normal新局重建，调用生产地图切换、光照、伤害、封灯、死亡、结局、存读函数及完整 `__steps`。测试状态暂停，autosave=false；先备份三个正式storage键，结束逐字节恢复。独立开发键 `__deep_light_p0_backup_v1` 支持中断恢复，下次点击先恢复遗留备份，再开始新测试；正常完成删除备份。不要在未恢复时另开游戏写存档。

为了隔离事件顺序，夹具移除NPC、抑制新波次，自造建筑、背包和第三站active状态；前两站完成也是夹具设置，不是实际采运或通关证据。信标使用营地原有人工光，不手填光照网格。敌人致死对照使用真实蚀芽攻击；自然黎明与断光对照证明不是所有试炼都会被夹具判成功。页面“通过”表示**现行行为被准确复现**，不表示下述缺陷已修复。P1须同步改掉已知缺陷的期望值。

## 生产事件顺序

`main.js: simStep` 先更新时间（跨天时可能自动保存），处理移动/跨区、封灯、交互和燃料，再依次运行SIM：

`updateWaves → updateEnemies → 搬运/塔/农业 → updateHazard → 净化/夜行/物流/NPC/心志/制造/冶炼 → updatePlayerSurvival → 技能/生态/手持`。

随后前哨、蚀痕、实体分离，才 `handleDeath`；最后整理敌人、重算脏光照、检测器。关键落点：`js/main.js`、`systems/waves.js`、`systems/resonance.js`、`entities/enemy.js`、`systems/survival.js`、`systems/combat.js`、`systems/seal.js`、`systems/ending.js`。

- 黎明 `updateWaves` 先结算共鸣，后消解普通敌人并移除Boss。
- 试炼守护/黎明结算检查地点、信标和光，但没有阵亡或主动撤退判据。
- 敌人更新末尾将零HP标为playerDead；`hurtPlayer`只减血、记伤，不置死亡标志。位于其后的岩浆等伤害会留下一个模拟步的零血量窗口。
- 死亡先封存背包/手持，再复归45%最大HP、饥饿35、伤势至少1、至少6秒无敌；清空当前敌人/Boss引用。只有 `300≤t<380` 跳到390，其余死亡不跳时间。
- 复归坐标是**当前地图中心偏右一格**，没有切回原点或地表。扣燃料是封存背包后的当前可支取量的一半（取整），不是全世界总燃料的一半。
- 封灯清燃料、扣队员心志并跳390，没有显式终止试炼。营地火等残余光可继续满足信标光判据。
- 结局名单用playerDead标志判断玩家是否倒地，不直接检查HP；当前局统计没有死亡/溃退的独立分类。

## 结论与下一步边界

**P1必须处理**：阵亡和封灯先终止正在进行的试炼，再清场/跳潮；自然潮落之前已有零HP不能先授成功；普通夜记录溃退而非靠清场假称守住。用有界结果记录支撑存读和后续恢复提示，旧档不补猜，旧结局不追溯撤销。自然胜利、断光失败、失败后重试必须保留。

**已否定的假设**：死亡清Boss会发击破奖励。15/17对照证实没有，P1保留回归，不重写已正确的Boss奖励逻辑。

**单独登记、暂不顺手修**：回营文案与当前层/区块中心复归不符；非空重复死亡覆盖旧包；晚于敌人更新的伤害延迟死亡标记。最后一项涉及P1的零HP时序，需在P1统一处理，不用再加资源惩罚掩盖。复归地点与遗落包保留策略另立小步，不在本次审计擅自修改。

没有证明所有种子、所有站点布局、每一种伤害来源或完整30分钟体验；本步证明最小边界及当前生产调用顺序。跨天自动保存顺序为静态观察，不宣称已经复现跨天致死存档竞态。本步不新增每帧扫描/模拟缓存，因此未重跑性能压力门，不把R6历史性能当本轮测量。
