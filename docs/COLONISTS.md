# D 拓荒者轴计划 · W16-D

> 目标：把拓荒者从“自动采集单位”升级为能被记住、被调度、会受伤、会失去也可能被救回的殖民地成员。玩家既是指挥官，也是能亲自下场的一员。
>
> 状态：**N7 已完成（2026-09-18）。** N7a 的地图身份标记、N7b 的个人经历记录，以及完整招募→远征→救援/死亡→关系→存读验收均已完成；本阶段没有新增等级、词条或无限资源。

## 设计底线

- 玩家不退出世界：任何指令都可由玩家亲自执行或介入，玩家是成员而不是上帝视角菜单。
- 拓荒者不是耗材：死亡、救援、关系、岗位与外观都必须留下可见后果。
- 不做无休止的随机特质、数值词条或经验等级；人格必须改变具体行为与决策。
- 命令是“意图”，不是瞬移脚本：NPC 会报告风险、需要路径和补给；危险夜间的命令仍有代价。
- 任何跨区块结算都遵守三活跃区块上限；无人区块不跑 AI、不离线生产。

## 当前基础与缺口

| 已有基础 | 当前缺口 |
|---|---|
| 饥饿、士气、心志、羁绊、墓碑、蚀化、工具、夜间指令 | 没有清晰的个人履历、职业和视觉辨识 |
| 采集/建造/炼油等自动工作逻辑 | 工作选择偏规则堆叠，缺少可解释的优先级与玩家调度层 |
| 休整位、医疗站、死亡履历、受限复苏、遗落包、区块坐标 | 前哨驻守、跨区块救援与多人协同仍待 N6/N7 |
| 玩家可移动、建造、战斗、背负结构 | 玩家与 NPC 没有统一的任务与协同模型 |

## 最终体验

玩家应能说出类似的话：

> “岚擅长矿脉，怕黑，所以我让她白天驻守碎岩台地；昨夜她在外面倒下，是玩家带着灯去把她拖回来的。她和槐关系很深，槐之后几天都不愿独自夜班。”

这句话中的每一部分都必须有对应的可观测机制，而不是档案里的装饰文字。

## 角色模型

每名拓荒者采用有限、可读、可存档的数据结构：

| 层 | 内容 | 玩法作用 |
|---|---|---|
| 身份 | 名字、头像/色板、出身短句、加入日期 | 视觉与记忆锚点 |
| 职业 | 采掘、营造、机工、守望、行医中的主职与副职 | 决定可承担的高效工作，不做等级树 |
| 擅长 | 2 个正向行为倾向 | 例如采掘快、夜守稳定、救援快 |
| 性格 | 1 个性格与 1 个忌讳 | 改变风险阈值、社交、休整与命令响应 |
| 状态 | 生命、饱食、伤势、心志、疲劳、倒地/死亡 | 直接影响今天能否派遣 |
| 关系 | 少量羁绊、恩怨、救命记录与失去记录 | 影响组队、心志与纪念 |

特质总量受限：每人“主职 + 副职 + 2 擅长 + 1 性格 + 1 忌讳”，所有效果写在数据表并可由 `__crew()` 穷举，不允许无限随机池。

## 指挥与行为架构

采用三层，不让 UI、寻路和工作规则互相抢控制权：

```text
玩家意图（区域 / 优先级 / 禁止项）
        ↓
任务板（采集、施工、搬运、守卫、救援、休整）
        ↓
个人决策（能力、危险、饥饿、关系、路径成本）
        ↓
执行状态机（取工具 → 前往 → 执行 → 交付 / 中断 / 报告）
```

- 玩家可圈定工作区、指定前哨驻守、设定“禁止夜班/禁止远行/优先救援”。
- 每名 NPC 有一个明确的当前任务与中断原因；悬停可读出“为什么不做”。
- 任务板每秒或事件触发时重排，不能每帧为每人扫描全图；按距离、技能、危险、饥饿、命令权重打分。
- 玩家可手动接管一项任务；NPC 看到玩家已处理后会重新选任务，不与玩家争同一格。

## 倒地、救援与死亡

死亡分为三个阶段，避免“血归零立刻删人”或“死亡毫无代价”：

1. **倒地**：生命归零后进入有限倒地窗口，停止工作、可被敌人威胁；地图与名册显示位置。
2. **救援**：玩家或具备救援资格的拓荒者可拖带/护送倒地者到光源、铺位或医疗设施；救援消耗时间、补给与防守窗口。
3. **死亡或复苏**：窗口耗尽、遭受额外伤害或救援失败则死亡并留下墓碑与关系后果；成功救回后带伤势、恐惧和一段恢复期，不能立即投入夜班。

“救活”不是无条件复活：后期可研究一次性救治手段或余烬仪式，但必须消耗稀缺资源、留下长期伤势或记忆代价，且不撤销已经发生的关系后果。

## 与现有核心的联动

| 系统 | 联动 |
|---|---|
| 光 | 倒地救援依赖可达光路；夜守者、怕黑者、静默前哨对光的选择不同 |
| 蚀潮 | 指挥官决定谁守灯、谁撤、谁救人；救援让“多撑一秒”有故事与代价 |
| 生存 | 食物、热食、铺位、伤势决定谁可派往远征，不再只是侧栏数字 |
| 生态 | 不同职业更适合观察、采掘、驯避或处理特定群系的生态线索 |
| 前哨 | 驻守者是活跃区块的理由；无人前哨冻结，不产生免费收益 |

### N4b · 拖带、护送与恢复期 ✅

- 稳定读条后若存在已完成的简易铺位，救援进入“护送”阶段；玩家需与伤员保持 `3.2` 格内并把人带回铺位，NPC 救援者会走到铺位相邻的可站格，避免把建筑格当作寻路目标。
- 护送有 `30s` 上限，蚀兽、失去光照、距离拉开或目标失效都会中断；中断不会重复扣除食物/燃料，也不会把伤员直接判死。
- 护送成功后伤员进入简易铺位，获得 `45s` 恢复期；恢复期内保持 `rest`，不能立刻重新上夜班。没有铺位时保留 N4a 的原地救回兜底，同样进入恢复期。
- 存档保存救援阶段、伤员/救援者稳定 ID、铺位坐标与恢复计时；读档后不会复制救援会话或吞掉倒地者。

### N4c · 医疗站与有限治疗队列（本步范围）

- 新增研究「蚀抗体质」后的医疗站：只治疗已经救回、仍处于恢复期且在医疗站覆盖范围内的拓荒者，不负责倒地读条，也不负责复活。
- 每座医疗站只有 1 个治疗位；全队最多同时排队 2 人。治疗启动消耗 1 燃料，治疗期间必须保持人工光照，失去光照或医疗站被破坏就暂停并退出治疗位，不退已经消耗的燃料。
- 行医职业节点先以“治疗速度 ×1.35、救援中断后更快重新排队”落地；不增加等级、经验或随机词条。
- 治疗完成后清除救援伤势并恢复到当前恢复期允许的生命上限；治疗只在当前活跃区块结算，不做跨区块或离线医疗。

**N4c 判据**

1. 未研究或未建成医疗站时，N4b 行为完全不变；医疗站不可建在营地火、潮穴、蚀痕或工地上。
2. 一名伤员可从“恢复中 → 排队 → 治疗中 → 伤势清除”完整走通；两名伤员同时出现时最多 2 人进入队列，单站同一时刻只治疗 1 人。
3. 治疗至少消耗 1 燃料；黑暗、站点失效、伤员死亡或换区块不会产生幽灵治疗者、重复扣料或跨区块结算。
4. 医疗站状态、队列和伤势字段可存读；旧档没有这些字段时按空队列兼容。

本步不引入跨区块救援、离线医疗结算、复活仪式或新资源；后续再单独评估“行医”对现场救援资格的影响。

**N4c 实测记录（2026-09-18）**

## 性能与存档约束

- 任务板只处理活跃区块，最多 3 个；每名拓荒者最多 1 个当前任务与 1 个候选缓存。
- 路径仅在任务改变、障碍改变或卡住时重算；不做每帧全员全图寻路。
- 关系图只保存有限边（例如每人最多 4 条显著关系），不构建 O(n²) 社交模拟。
- 存档只保存身份、状态、关系、命令、当前任务的可恢复描述；寻路缓存、UI 悬停、临时评分不存。
- 任何“复活”都必须有次数/资源/后果上限，不能成为资源或战斗漏洞。

## 创意储备（不进入首版，待核心稳定后挑选）

- **灯下誓约**：两名有羁绊的拓荒者可在同一灯下互相担保，一人倒地时另一人更可能冒险救援，但两人同时失去会造成更强的心志崩塌。
- **遗志工具**：死亡者的一件常用工具可被继承，保留的是“工作习惯”而非数值词条，例如继承者在相同工作首次遇险时获得一次提示或撤离优先级。
- **失联电台**：远方前哨在休眠前留下最后一条短报；玩家必须决定是否点亮灯塔去回应，回应会增加光压却可能救回人或发现生态线索。
- **玩家的身体**：玩家受伤、饥饿或倒地时，NPC 不会继续机械执行命令；他们会按性格决定护送、继续任务、恐慌或违令撤退。这让“既是指挥官也是成员”真正成立。

## 固定约束

- 不加入经验等级、职业升级树、装备词条池、无限招募或无限复活。
- 不让人格变成纯随机惩罚；所有负面倾向必须有可预判、可管理的表现。
- 不让 NPC 自动处理一切：玩家亲自执行、临场救援和灯光布局始终有不可替代的价值。
- 每一步完成后同步本文件、`docs/BUG_HUNT.md`、`HANDOFF.md`；玩家可见界面变化同步 `README.md` 与 `docs/COPY.md`。
