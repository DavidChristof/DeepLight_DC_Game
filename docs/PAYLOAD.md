## 1. 设计决定（含与《Noita》的关键取舍）

**取舍：要组合的「质」，不要组合的「量」。** Noita 的"无数种"来自自由参数与任意法术；本作要的是**玩家能理解、能记住、平衡能算清**的组合。所以：

1. **发射器 = 塔的种类**（`辉光塔=beam` / `震荡塔=burst` / 计划中的 `连锁光塔=chain`）。
   *为什么不把发射器做成可换的槽*：塔的种类决定外观、成本、hp、工期，且**已经**写在存档的 `type` 里；把发射器做成槽会同时动建造/存档/面板三处，换来的只是"同一个塔基座能换炮"，而**修饰器已经提供了 22 种载荷**。第 6 步若要"换装发射器"，那时候再做成研究解锁的改装，比现在硬塞更稳。
2. **修饰器 = 可装配的槽位**（1→3 槽，研究解锁），**每个修饰器占 1 槽、效果相乘**（乘法交换 → 顺序不影响结果，面板因此不强调顺序，文档里明说）。
3. **形状类修饰器最多装一个**（`scatter` 散射 / `pierce` 穿透天生长矛盾）：面板会拒绝第二个并给出提示。这条把组合空间从"堆叠"压成"可读懂的选择"。
4. **越强的塔越吃灯**：基础发射器**不直接耗燃料**（沿用现状：塔靠"所处光照"吃饭，灯的燃料就是它的口粮）；**每装一个修饰器 +0.1 燃料/发**。于是"3 槽满配"的塔一晚要多喝约 20 燃料 —— 强度有明确价格，且**0 槽塔的账本与今天完全一致**（这让 2b 步能做"零玩法变化"回归）。
5. **不做自由参数**：修饰器没有可调数值、没有脚本接口。组合数**可穷举**（下表 66 个），这既是平衡手段，也是能不能写断言的生死线。

## 2. 数据模型（`js/data/payload.js`，新建）

### 2.1 发射器（绑定在塔的种类上）

| id | 塔 | 单发 | 冷却 | 射程 | 对空 | 形状 | 伤害类型 |
|---|---|---|---|---|---|---|---|
| `beam` | 辉光塔 | 16 | 0.9s | 6.5 | ✓ | 单体 | `light` |
| `burst` | 震荡塔 | 7 | 2.4s | 4.5 | ✗ | 环 2.2 格 + 减速 0.5/1.6s | `shock` |
| `chain` | 连锁光塔（2e） | 16 | 1.6s | 5.5 | ✗ | 命中后跳 2 格内下一目标，每跳 ×0.6（最多 3 跳） | `light` |

> 现行数值一字不改（`beam`/`burst` 就是今天的辉光塔/震荡塔），所以**引擎行为是"加了一层描述"而不是"改了一遍实现"**。

### 2.2 修饰器（5 种，每个占 1 槽、+0.1 燃料/发）

| id | 名字 | 效果 | 数值 | 备注 |
|---|---|---|---|---|
| `focus` | 聚焦 | 伤害↑ 射程↓ | 伤害 ×1.6 · 射程 ×0.7 | 单目标爆发 |
| `scatter` | 散射 | 目标数↑ | 主目标 2 格内**再加 2 个目标** · 伤害 ×0.6 | 形状类（多目标） |
| `pierce` | 穿透 | 打一条线 | 沿线敌人各吃 ×0.8（最多 3 个） | 形状类（多目标） |
| `chill` | 迟滞 | 命中减速 | 伤害 ×0.85 · 减速 0.5 / 1.6s | 控制 |
| `purify` | 净化 | 命中处蚀痕 −1 级 | 伤害 ×0.7 · 半径 1.5 格 | **与生态轴（C）挂钩** |

### 2.3 唯一的计算函数（关键）

```js
// 面板 / 悬停 / HUD / __lab() / __dps() 全部只走这一个函数；任何地方自己算一遍都算 bug
payloadStats(load, state) → {
  名字, 单发, 每秒, 燃耗每秒, 每发燃耗, 射程, 目标数, 类型,
  减速: {mul, secs} | null, 净化: radius | null, 冲突: [id] // 非法组合的说明
}
```

- `名字` 由修饰器名 + 塔名拼（`聚焦·散射 辉光塔`）—— 名字也来自同一张表，不许另写一份。
- **缓存**：结果挂在建筑实例上（`b._ps`），只在 `load` 变化 / 研究变化 / 技师变化时失效（每帧每塔重算 = 白烧 CPU）。

## 3. 组合空间与数值门

### 3.1 组合数（可枚举、可断言）

修饰器 5 种，形状类 `{scatter, pierce}` 互斥；槽数 k = 0/1/2/3：

| 槽数 | 组合数 | 说明 |
|---|---|---|
| 0 | 1 | 空载（= 今天的塔） |
| 1 | 5 | 5 选 1 |
| 2 | 9 | C(5,2)=10 减去 `{scatter,pierce}` 这 1 对冲突 |
| 3 | 7 | C(5,3)=10 减去含两个形状类的 3 种 |

**单塔载荷 22 种 × 塔数 = 全部组合**（当前 2 种塔 = **44**；2e 加上「连锁光塔」后 = **66**）。
`payload.count` 断言这个数字与枚举实现一致（表变了却忘了改文档 → 报）。

### 3.2 数值门（防的是"未来某次改表失控"）

对**每一个**组合断言：`0.3 × 该塔基准单靶DPS ≤ 组合单靶DPS ≤ 6 × 该塔基准单靶DPS`。

- 由表可算：单靶乘子 ∈ [0.7×0.85×0.6, 1.6³] = **[0.357, 4.1]** → 上下限门必然成立；
- 一旦有人把某个修饰器改成 ×2.5，断言当场报（这就是这条门的价值：**它不调平衡，它守平衡**）。
- **多目标维度单独报告**（`__lab()` 里给"对 3 只标准蚀芽的有效 DPS"）：`scatter`/`pierce` 的单靶 DPS 天生更低，它们的价值在目标数上——只有把两个维度都印出来，"哪个组合强"才不是错觉。

### 3.3 燃料预算（`beam` 0.9s/发，一个蚀潮夜 ≈ 60s）

| 载荷 | 每发燃耗 | 每秒 | 一晚（1 塔） | 3 塔同配 |
|---|---|---|---|---|
| 0 槽 | 0 | 0 | 0 | 0 |
| 1 槽 | 0.1 | 0.11 | ≈ 6.7 | ≈ 20 |
| 2 槽 | 0.2 | 0.22 | ≈ 13 | ≈ 40 |
| 3 槽 | 0.3 | 0.33 | ≈ 20 | ≈ 60 |

> 对照：灯柱 1 燃料 / 18 秒 ≈ 0.055/秒。**满配 3 塔 ≈ 6 盏灯的油耗** —— 这就是"燃料 = 法力"的价格标签。
> 扣料纪律与光爆**完全一致**：走容器账本（`withdraw` 同一条路径），**扣不出燃料就不开火**（HUD 提示"燃料不足，塔熄火"）。塔内部累计小数债务，满 1 才真扣 1（`payload.ledger` 断言守恒）。

## 5. 存档与旧档迁移

1. `core/save.js` 的 `snapshot()` 里给建筑加一个字段：`mods: b.mods || null`（空载写 `null`，省体积）。
2. `main.js` 的 `restoreBuildings()`：`mods: Array.isArray(b.mods) ? b.mods : (EMITTER_OF[b.type] ? [] : null)` —— 老档没有 `mods` → 空载，**行为与老版本完全一致**。
3. 非法值兜底：`mods` 里出现未知 id / 超过槽数 / 形状类重复 → 该塔读入时**清空载荷并在 HUD 提示一次**（不静默、不崩）。
4. 回归口径沿用 B26/B27 的方法：**12 组随机时刻存/读往返 0 差异**（指纹含 `mods`）+ 一份"老格式存档"（手工删掉 `mods` 字段）读入不炸。
5. `__check` 新增 `build.load`：每座塔的 `mods` 合法（id 在表里、数量 ≤ 槽数、无冲突）。

## 8. 性能口径

- `__lab()` 穷举 66 组合是**纯计算**（毫秒级），只在你手动调用时跑；
- 热路径开销 = 每塔每发一次 `payloadStats`（已缓存，只在载荷/研究/技师变化时失效）；
- 实测口径：`__watch(false)` 下的 `__steps` 长跑每步耗时（**别忘了 D35：开着巡检量耗时会虚高 20 倍**）；
